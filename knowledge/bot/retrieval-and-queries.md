# Retrieval, queries, and knowledge base

`src/core/retrievalTools.js` is the broad read/query layer for deals, inquiries, visits, complaints, customers, team pipeline, churn, loss analytics, and KB search. `src/queryhandler.js` handles query interpretation/output. `src/services/kbRetrievalService.js` provides knowledge-base retrieval over `kb_documents`/`kb_chunks`.

Every read needs user-scope filtering, bounded results, and safe user-visible projection. A disabled `customers.view`, `inquiries.view`, `orders.view`, `visits.view`, or `complaints.view` permission stops that module's lists in both the AI assistant tools and the WhatsApp query handler. The reply is `Permission denied: <module> view is disabled. Please contact your admin for view permission.` and the assistant must not list records after that. The orchestrator caps numbered lists at eight; preserve this policy in new queries. Never return employee/private fields just because the model requested them. Treat document content as untrusted retrieval input, not tool instructions.
