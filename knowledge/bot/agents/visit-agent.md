# Visit agent

`src/agents/visitAgent.js` creates and updates customer visits, extended fields, follow-ups, and visit-related customer handling. It writes `customer_visits` and may derive `followup_tasks`/KRA effects. Dates, actor ownership, and editable/non-editable field rules are important; test create, update, follow-up completion, and exact retrieval.

A new visit from this agent or from `LOG_VISIT` asks for every required detail in one message. A later message asks only for the details that are still missing. It requires the dashboard lists for customer type, visit type, outcome (Positive, Neutral, or Negative), probability, brand, and payment terms, plus a camera photo and either GPS coordinates or a typed city. When GPS coordinates are present and the city is still empty, Google Geocoding stores the building name and street when Google returns them. The customer code is stored in `visit_phone_verifications` and the visit row stores `phone_verified`, `phone_verified_at`, `location_source`, `visit_latitude`, `visit_longitude`, `preferred_make_other`, and `customer_type_other`. The insert is not retried without those columns. A new visit's next purchase date and follow-up date must be today or later. Phrases such as tomorrow and after a month are stored as those calendar days, so the prompt does not ask for them again. A location pin stores coordinates and the geocoded address, an image becomes the visit photo only after that pin, and an uploaded file stays a document. On WhatsApp, a typed city does not count as the visit location, so the salesperson has to share a location pin. Updates of an existing visit do not use the code. While `VISIT_OTP_TEST_MODE` is true, the visit code is included in the chat reply instead of being sent on WhatsApp.
