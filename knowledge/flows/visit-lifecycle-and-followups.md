# Visit and follow-up lifecycle

Visits originate from `VisitsPage` or `visitAgent`, are persisted in `customer_visits`, and can create/update `followup_tasks` and KRA-related activity. New visits created in the dashboard are saved only after `POST /kra/visits/otp/verify` returns a token that `POST /kra/visits` consumes. A new bot visit uses the same `visit_phone_verifications` code before it writes `customer_visits`. Update flows must preserve their field authority and use a specific visit identity; never update a guessed latest visit. Follow-up completion should update the same canonical record, then refresh dashboard/action-queue data. A salesperson can mark a follow-up done or reopen it on a visit they own. Other visit edits stay limited to managers and administrators.
