# Assistant and intelligence

`AssistantPage.tsx` sends text, image, and GPS payloads with `chatbotApi` to `POST /chat/message`, which the backend forwards to the bot. The paperclip offers Upload from device for an optional document and Capture an image, which opens the visit camera over the whole page, stamps the GPS, and rejects a photo without coordinates. Procurement sees AI Assistant in the nav. The suggested prompts and the bot reply use the same interactive buttons as WhatsApp: pending prices, all inquiries, and log a base price. A procurement manager also gets My team. All inquiries counts every Inquiries-table status badge, lists the newest 10, and says to type next for the next set. Pasting a procurement number or the whole line from that list returns the inquiry details. Log a base price lists the first 7 inquiries whose pricing status is exactly awaiting price, as text with the date and time and every product line, and says to open the Inquiries tab when more are waiting. Choosing an inquiry asks for one line, then saves a base price or an unavailable note on that line only. A clicked menu button is shown by its name, such as All inquiries or Log a Base Price. Cancel ends the current step and hi shows the menu again. A question such as how many inquiries a salesperson has left to price is answered with that count. Sales still uses the catalog menu, then *Price this inquiry* after the base price is ready. `IntelligencePage.tsx` presents business intelligence. Intelligence shows Sync Bigin only for a signed-in admin or salesperson. The backend client uses a 120-second assistant timeout. Interactive chat components may call bot-focused paths depending on deployment configuration.

Keep retries idempotent for mutation-capable messages, avoid logging prompt/image contents, and render model output with the existing markdown safety components rather than raw HTML.
