# Procurement pricing

Procurement users work on `/inquiries`. `/procurement` redirects there. Customer name, phone, email, and raw inquiry text are removed from procurement API responses. Product lines, quantity, unit, and delivery location stay. The inquiry id and the procurement number (`PR-10001`) are both shown. The procurement number is the pricing-case id. The inquiries search matches that number, the salesperson, the product lines, and the delivery location. Kanban View opens the pipeline on the first click.

A procurement person or procurement manager can edit only the base price. Description, HSN, and quantity are read-only. Transport, loading, credit, and margin are hidden. The line amount is the weight already shown in MT times the per-MT rate. A missing weight makes that amount 0. Subtotal, GST, and the grand total follow those line amounts. Quantity totals and the weight total stay as they are. The drawer has one save control for them, Save Prices, in the sticky footer. The click shows Saving until the request finishes, then a success toast. A rejected save shows the server error and leaves the status unchanged. A later list refresh does not replace a newer pricing status, such as Price Ready, with Awaiting Price, and it does not clear a base price that is still being edited. A blank base price also has an optional note, stored as the reason that line is unavailable. A salesperson still has Save Prices and the footer Save. The drawer has one quotation button, Send quotation, which becomes Share Again after a quotation has already gone out. The email modal keeps its header and actions visible and scrolls the message. After the salesperson save, base, transport, loading, credit, and margin collapse into the Rate column. Credit is rupees per MT and is added into the rate; a blank credit is zero. The rate cell still opens those five components, and a later inquiry refresh does not replace that saved rate with zero. The GST column uses the same tax split as the total, so a saved row shows 18% IGST, or CGST and SGST inside Maharashtra, on the line amount. That amount is the displayed MT weight times the saved sell rate, including when the inquiry line has no amount of its own, and a later list refresh does not put the amount or GST back to zero.

An admin assigns salespeople to a procurement person in the control panel. Inquiries for those salespeople are created with that person's `procurement_employee_id`. A procurement person who can see an inquiry can save its base price. That includes an unstamped inquiry whose salesperson is known from the sender or the customer owner, not only from the stored salesperson phone. An inquiry already owned by someone else stays with that owner. A salesperson sees that saved base price when their `employees.id` owns the inquiry, including an id stored on the inquiry, the deal, or the employee row for the salesperson or customer owner. A phone string by itself does not open the price. A procurement manager sees every inquiry stamped to a person on their team, plus unassigned inquiries for those persons' salespeople in any status.

## Workflow

1. A new inquiry starts as `awaiting_price`.
2. Procurement saves base prices with `PATCH /inquiries/:id/procurement-pricing`. A positive base price is available. A blank base price is unavailable. If the `credit_per_mt` column is missing, the save retries without it. A failed `pricing_status` update fails the request.
3. At least one available line makes the inquiry `price_ready`. Every line blank makes it `unavailable`.
4. Sales saves transport, loading, credit, and margin with `PATCH /inquiries/:id/sales-pricing`. The server stores `rate = base + transport + loading + credit + margin`. The taxable amount is that rate times the line weight in MT, using the same weight conversion as the drawer. A blank credit is 0. Maharashtra is CGST 9% + SGST 9%. Every other delivery state is IGST 18%. The same step is available in the assistant with *Price this inquiry* once the inquiry is `price_ready`.
5. Quotation sending uses those saved rates for available lines. When every line is unavailable, sales can preview and send a decline email.

Procurement cannot create inquiries, send quotations, or move an inquiry to confirmed, won, or lost. The same limits apply in WhatsApp and the AI Assistant. There they can list pending and current inquiries, log a base price, and, for a manager, see the team. A later base-price save does not wipe credit, transport, loading, or margin. Apply `supabase-inquiry-line-credit.sql` before credit can be stored.
